## 原始训练机制

完整 12 关节通过位置目标控制：目标角 = 默认关节角 + 0.25 × action；PD 为 Kp=40、Kd=1。仿真步长 0.005 秒、decimation=4，策略频率 50 Hz。默认 4096 环境、每回合 20 秒，初始机身高度 0.42 米，目标高度 0.52 米。

Actor 输入 45 维：角速度 3、重力投影 3、命令 3、关节位置 12、关节速度 12、动作 12。Critic 输入 86 维：线速度 3 + Actor 45 + 域随机参数 34 + 四脚接触 4。源码在域随机输入里重复拼接 restitution，两项都保留以保持原始接口。

命令前向范围 −0.2～0.6 m/s，横向为零，启用目标航向控制，每 10 秒重采样。采样代码另有 20% 全零命令、独立 10% 平面速度归零和小于等于 0.1 m/s 的平面命令死区。源码注释中的“5%”与实际阈值不符。启用航向模式后，每步会重算转向命令，因此“全零采样”不保证后续转向始终为零。

23 项非零奖励及原始权重保存在 [来源清单](upstream_manifest.json) 的 `validation.reward_terms`。主要机制如下：

| 项目 | 原始机制与权重 |
| --- | --- |
| 直立 | 重力投影误差平方 −1；高度指数奖励 +1.5 |
| 前腿抬起 | 两前脚离地 +0.4；前脚接近 0.67 m 高度的指数奖励 +5 |
| 速度跟踪 | 平移 +2.5、转向 +2.5，指数分母 0.25 |
| 后腿步态 | 1.6 秒周期，6 cm 正弦抬脚目标 +0.4；恰好一只后脚接触 +0.3 |
| 姿态与动作正则 | 关节偏移、髋关节、左右对称、动作变化、扭矩、加速度、碰撞与限位 |

直立后的速度映射使用机身 `-Z` 对应前进、机身 `X` 对应转向轴，不能直接当成普通四足的机身 X 前进。权重在运行时乘策略步长 0.02 秒。

网络为 Actor/Critic 各 `[512,256,128]`、ELU；PPO 每轮每环境 24 步、5 epochs、4 minibatches，学习率 0.001，自适应 KL=0.01，clip=0.2，gamma=0.99，lambda=0.95，entropy=0.01。启用镜像对称损失，系数 1。默认 15000 轮、每 100 轮保存。

## 源码分析中应关注的限制

以下是由源码直接推导的机制问题，不是已运行实验得出的结论。本次保持环境和配置原样，尚未修改这些机制。

- `rew_hanstand` 是所有环境高度分数的平均值，多个奖励用其是否超过 0.70 作为开关，会造成环境之间耦合。
- 奖励调用顺序由配置字典决定；`base_height` 更新该共享变量，排在它前面的门控项可能读取上一仿真步的分数。
- 步态相位按回合时间生成，但 45 维 Actor 输入不含相位，且策略是无记忆 MLP；这使相位奖励的时间信息不能直接被策略观测。
- 接触奖励仅要求一只后脚着地，没有要求着地脚与期望相位一致；单侧支撑也可能获奖。
- 后腿关节也受到左右对称和目标关节角正则，可能与交替步态产生竞争。
- `feet_clearance` 对 6 cm 目标误差使用 `exp(-10*abs(error))`；脚不抬时在峰值仍约有 0.549 的单脚分数，抬脚约束并非硬要求。

因此，这份工程具备原作者的直立行走训练机制，但不能仅凭仓库名称或已有模型文件断言新训练一定能形成稳定交替行走。应先运行原版短训练，再观察速度、后脚交替支撑、前脚触地和终止情况。

## 本次工程改动

环境 `Go2_Handstand.py`、配置 `Go2_Handstand_Config.py`、URDF/DAE 与固定提交逐字一致，没有调整奖励、权重、控制、网络或 PPO 超参数。

仅清理无关任务和算法的导入、导出与辅助代码，设置默认任务为 `go2_handstand`，补充最小安装配置。PPO 的两张镜像矩阵由硬编码 `.cuda()` 改为 `device=self.device`，以支持实际选择的设备和 CPU 算法验证；矩阵与损失公式不变。

回放增加 `--speed` 和 `--yaw_rate`，关闭航向重算，并在每次策略计算前写入指定命令、刷新观测，防止 reset 采样覆盖评估命令。默认前进 0.2 m/s、转向 0。绘图使用 Agg 后端，不依赖 Tk；不提供交互曲线窗口。训练入口不使用这两个回放参数。回放保留上游其他域随机设置，但关闭推扰动和观测噪声。

逐文件上游与本地 SHA-256、修改标记见 [upstream_manifest.json](upstream_manifest.json)。

## 安装与运行

使用独立、已经安装 NVIDIA Isaac Gym 的 Python 环境。上游 README 使用 Python 3.8；Isaac Gym 是此工程依赖的仿真器。以下命令在本工程根目录运行；采用 editable 安装以正确定位根目录的机器人资源。

```bash
# 激活准备好的 Isaac Gym 环境后，先验证真实仿真依赖
python -c "import isaacgym; import torch; print(torch.__version__, torch.cuda.is_available())"

# 如尚未注册已存在的 Isaac Gym 源码，使用其真实路径安装
# python -m pip install -e /实际路径/isaacgym/python
python -m pip install -e ./rsl_rl
python -m pip install -e .

# 先做仿真短训练，确认资源加载、接触与奖励能运行
python legged_gym/scripts/train.py --task go2_handstand \
  --num_envs 64 --max_iterations 3 --run_name smoke --headless

# 从头训练：沿用参考仓库参数
python legged_gym/scripts/train.py --task go2_handstand --headless

# 指定实际运行目录名与 checkpoint 编号续训
python legged_gym/scripts/train.py --task go2_handstand --resume \
  --load_run <运行目录名> --checkpoint <编号> --headless

# 分别检查前进与零命令行为；有显示环境时去掉 --headless
python legged_gym/scripts/play.py --task go2_handstand --num_envs 16 \
  --load_run <运行目录名> --checkpoint <编号> --speed 0.2 --yaw_rate 0 --headless
python legged_gym/scripts/play.py --task go2_handstand --num_envs 16 \
  --load_run <运行目录名> --checkpoint <编号> --speed 0 --yaw_rate 0 --headless
```

输出位于 `logs/go2_handstand/`。回放会按上游方式导出 `exported/policies/policy_1.pt`。日志、权重和导出策略均已加入 Git 忽略规则。
